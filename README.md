# Personal portfolio projects

Four reproducible personal projects by Minwoo Jeong covering business decision analysis, trading-system data structures and service reliability. Built with AI assistance in October 2026; reported metrics and verification results are generated by the included code. These are educational prototypes, not employer deployments or live trading systems.

## Reproduce

Use Python 3.12 and a C++17 compiler (g++ on PATH). From this folder:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run_all.py
```

The analytics commands download two small archives from the official UCI repository on first execution; subsequent runs reuse the local archives. SHA-256 hashes and split sizes are recorded in the result JSON. Raw datasets, temporary dependencies and executables are not intended for version control. All four projects run locally; none connects to a broker, places real trades, changes routing or scans a customer network.

## Projects and deliverables

| Project | Purpose | Entry point | Evidence |
|---|---|---|---|
| [Campaign Budget Prioritization](campaign_budget/) | Business decision and model-risk assessment | `campaign_budget/analysis.py` | Executive brief, budget curve, held-out scores, 10 tests |
| [Demand and Service Capacity Planning](capacity_planning/) | Cost-sensitive operations planning | `capacity_planning/analysis.py` | Executive brief, holdout capacity, scenario comparison, 9 tests |
| [C++ Orderbook and Replay Engine](orderbook/) | Data structures, order lifecycle, risk controls | `orderbook/verify.py` | 16 C++ tests, 5,000-command replay, independent 2,000-command oracle |
| [Service Health and Incident Monitor](service_monitor/) | Backend API, SQLite state, failure handling | `service_monitor/monitor.py` | Dashboard, local HTTP API, persistence and integration tests |

HTML briefs are in the two analytics `reports` folders. `verification.json` records the full-suite result. Each project has its own README, test cases and limitations.

## Interpretation and limitations

Campaign ranking did **not** beat a simple historical-success rule on the chronological test; the decision brief recommends prospective validation instead of model deployment. Capacity cost improvements are scenario calculations, not actual savings. The orderbook is single-threaded and not exchange-ready. The monitor measures sampled health, not continuous uptime. Each project documents its assumptions, test boundaries and next steps.
